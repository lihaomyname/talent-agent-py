# 多模态匹配部署与回滚

## 数据与业务约定

复用现有消息、计划、澄清和运行表的 JSON 字段，本变更不新增表、不改字段、不运行迁移。候选人不删除且均可查看是本期业务前提；历史结果校验会话所有者与租户后直接读取数据库，不重新调用 Java 复核人选。

原图仅在提取请求中使用，不保存到聊天或数据库。只保存提取文字、需求、白名单经历和证据。Cookie 和模型密钥不写入快照。所有业务状态以数据库为准，不新增资料缓存；运行对象结束即释放，容量限制不删除历史。

## 部署顺序

1. 执行 `uv sync` 安装 Pillow 和 multipart 依赖。
2. 保持 `TALENT_AGENT_ENABLE_MATCHING=false` 部署双版本读取，先确认旧搜索、分页、历史正常。
3. 文本匹配沿用已有文本模型配置。视觉需显式设置 `TALENT_AGENT_VISION_BASE_URL`、`TALENT_AGENT_VISION_API_KEY` 和 `TALENT_AGENT_VISION_MODEL=deepseek-flash`；不自动复用文本密钥。
4. 设置 `TALENT_AGENT_ENABLE_MATCHING=true` 并重启服务。页面通过 features 接口判断截图入口是否可用。只改静态页面时刷新即可，修改后端配置必须重启。
5. 使用合成职位和经授权的测试资料验收，不以 Mock 测试替代真实语义准确率验收。

默认每轮目标 10 人、最多搜索 5 页、检查 50 人、模型尝试 20 次、120 秒；模型修复计入预算。累计最多 10 轮、500 人及 10 MiB 快照。固定搜索条件负责强制召回，其余要求都是偏好，只排序、不淘汰；不足 10 人如实显示。

## 历史与中断

刷新从数据库恢复。进程启动将遗留 V2 QUEUED/RUNNING 标为中断，不自动重发模型请求。用户从同需求的最新运行主动继续，继承未消费缓冲并排除已展示人选。旧需求结果保留，但不能从旧版本或旧祖先分叉继续。

## 回滚

关闭 `TALENT_AGENT_ENABLE_MATCHING` 并重启，停止新增多模态写入；保留本版本的 V1/V2 读取代码，已有匹配结果仍可读。不要直接回退到只认识 V1 JSON 的旧二进制，不删除 V2 数据，也不执行数据库降级迁移。

## 当前验收边界

自动化测试覆盖兼容读取、纯筛选交接、匹配与继续、幂等、预算、超时、取消、资料白名单和引用真实性。真实模型的语义准确性、Java 日期业务含义及生产延迟仍需独立验收；工作经历日期不会被直接当作专项技能年限，含义不明保持信息不足。
