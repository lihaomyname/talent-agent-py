# Code Review 处理说明

项目当前采用单实例架构，评审意见按“功能正确性”和“部署与运行能力增强”分开处理。

## 已处理

- 实体 `NOT_FOUND` 不再构造空选项卡片，改为“忽略 / 重新描述”。
- LangGraph 未分类异常统一结束 Run，避免一直停留在 `RUNNING`。
- LLM 网络异常统一转换为 `ModelOutputError`，保留有限 JSON 修复。
- “下一页 / 上一页”根据当前结果页计算，不再写死第 2 页。
- 停止操作不再覆盖已经成功、失败或被替代的终态 Run。
- `MESSAGE_INTENT` 和 `RESTATE` 澄清选项具备实际处理分支。
- 招聘接口兼容字符串 `code="200"`，校验分页数据和 `lastPage` 布尔类型。
- “杭州”可以匹配城市字典中的“杭州市”。
- Cookie 只允许发送到白名单 HTTPS 标准端口，并校验输入长度和控制字符。
- Prometheus 使用路由模板作为 path 标签，避免 Run ID 产生大量时间序列。
- HTTP、LLM、LangGraph 节点和招聘接口增加统一可读日志。

## 暂不处理

- 多实例并发、分布式锁和跨进程 Run 协调。
- LangGraph checkpointer 和跨进程恢复。
- 分页引用签名、历史 SearchPlan Schema 自动迁移。
- 完整网关身份体系和生产部署边界控制。
- 总请求 deadline、二次取消等生产级运行时增强。

用户可以在搜索运行时发送新消息。为避免两个请求短暂重叠时生成相同消息序号，
应用服务只保留一个简单的进程内消息写锁；这不是多用户并发方案。
