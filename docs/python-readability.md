# Python 类型与中文注释规范

方法签名应明确输入和返回类型，属性注释应说明业务含义。

## 方法类型

- 所有函数声明返回类型，包括 `-> None`；异步函数标注的是 `await` 后的结果类型。
- 所有参数声明类型，`self`、`cls` 除外；依赖工厂使用 `Callable`，外部能力使用已有端口接口。
- 固定结构的字典使用 `TypedDict`。Graph 节点的返回类型在 `orchestration/state.py` 定义。
- `TypedDict` 运行时仍是普通字典，不会像 Pydantic 一样自动进行运行时校验。
- `total=False` 表示键可以不存在；`SearchPlan | None` 表示键的值允许为空，两者含义不同。
- 多值元组暂时保持原结构，但返回注释必须说明每一项的顺序、含义和空值情况。
- 外部原始 JSON 或 Pydantic 动态序列化结果可使用 `dict[str, Any]`，随后在已有模型边界校验。
  不用 `Any` 掩盖已知的业务对象类型。

## 属性和枚举

- 领域模型、请求响应、配置、Graph 状态和节点输出字段就地添加中文注释。
- 注释说明业务含义，必要时包含单位、空值语义、写入来源或生效阶段。
- 枚举类说明用途，每个枚举值说明业务含义。
- ORM 字段已有 `comment=` 的中文数据库说明，不重复堆叠相同注释。
- 普通成员依赖在赋值处说明用途；跨方法创建的成员明确声明类型和初始化时机。

## 关键操作

重点说明消息幂等、事务提交、计划版本推进、澄清草稿恢复、实体编码来源、
Graph 分支、任务取消、分页版本绑定和异常转换的原因。
不为明显的赋值和返回重复添加无信息量注释。

Graph 节点方法注明读取哪些状态、返回哪些更新。节点返回的是部分状态，
由 LangGraph 合并，不要求返回完整的 AgentState。

## 验证原则

类型和注释完善应保留数据结构、分支、事务和调用顺序。
尤其不要随意修改 FastAPI/Pydantic 注解和 Field 参数，它们参与运行时契约及模型提示词 Schema。
